# Agent-driven CRM redesign

## Outcome

Reframe Talent Signal from a recruiter-specific relationship assistant into a
general, evidence-first relationship CRM whose configurable Agent coordinates
memory, imports, relationship understanding, proposals, and approved effects.
The work must produce a source-grounded product and engineering dossier, a
coherent mobile information architecture and visual target, a staged connector
and import design, an executable test program, and one verified implementation
slice that proves the direction without weakening identity, provenance, or
human approval.

## Decision question

How should the product combine Kin-like embodied long-term understanding,
Mesh-like relationship memory, Ohai-like proactive coordination, and
Paired-like reciprocal interaction without becoming a cluttered dashboard,
ambient surveillance system, or autonomous source of relationship truth?

The primary audience is the product owner choosing the next product identity
and implementation sequence. Engineers and designers should be able to resume
from the same evidence without reconstructing the research.

## Boundary

In scope:

- general relationship-CRM positioning and object model;
- dedicated Agent identity/profile, personal context, governed Memory, source
  connections, import status, and action-permission presentation;
- Today, Sessions, People, living person, capture, onboarding, and review roles;
- LinkedIn user-export import, vCard/CSV/device contacts, calendar, email, and
  screenshot/Shortcut capability analysis;
- duplicate resolution, provenance, freshness, revocation, deletion, retry,
  and partial-import behavior;
- current external product and public UX research;
- visual concepts, implementation sequencing, and executable evaluation gates.

Out of scope for the first implementation slice, but not rejected from the
longer direction:

- unsupported or unofficial LinkedIn scraping and continuous connection sync;
- ambient ingestion of private messages;
- unreviewed contact, calendar, message, CRM, or notification writes;
- a broad customizable field warehouse, sales pipeline, or relationship score;
- replacing the in-progress Agent-first contact orchestration owned by the
  existing dirty worktree.

## Current evidence and contradictions

- The repository already has a bounded Agent control plane, screenshot capture,
  People, Sessions, Today, Calendar projection, contact proposal/review, and
  recoverable receipts. These are foundations, not proof of a general CRM.
- Canonical product documentation previously defined independent recruiting as
  the permanent audience and named a full CRM as a non-goal. This plan resolves
  that contradiction by making relationship CRM the product direction while
  retaining recruiting as the first complete proof wedge.
- Existing design guidance already separates Today (attention), Sessions
  (intent), People (identity), and governed Agent operation. An embodied Agent
  needs its own destination and persistent entry, not a second competing home.
- The working tree contains substantial unrelated changes. New work must use
  separate files or non-overlapping ownership until integration is intentional.

## Completion evidence

- Every material market or platform observation has a current source and
  access date; weak anecdotal signals are labeled.
- The dossier exposes the recruiting-to-general-CRM contradiction and asks for
  or records the necessary product decision.
- The integration matrix distinguishes manual export, one-time import,
  read-only sync, proposed write, approved write, unsupported access, and
  deletion/revocation behavior.
- UI artifacts preserve the selected embodied-Agent direction while keeping
  Today, Agent configuration, People, imports, and action review semantically
  separate.
- The implemented slice is exercised on the real intended surface for normal
  navigation, empty and configured source state, explicit clearing, relaunch
  recovery, compact width, localization, and large text. Duplicate, partial
  import, revocation, and import receipts remain gates for the later executable
  import slice rather than claims of this configuration slice.
- Specialist reviews refer to the same frozen artifact; safety vetoes are
  resolved by passing their verification, not by code change alone.

## Re-plan triggers

- If current official platform terms contradict a planned connector, use a
  user-controlled export/import or signed handoff instead of an unofficial
  continuous sync.
- If broad CRM scope weakens the governed Pursuit/relationship model, keep the
  stable Person plus contextual relationship structure and change terminology,
  not truth ownership.
- If the embodied Agent competes with Today or causes configuration overload,
  keep its persistent avatar entry but move setup and source management into a
  dedicated Agent destination.
- If research cannot resolve a product preference, run a discriminating
  prototype test rather than presenting model taste as a decision.
