# GET-5 iOS Session interaction

## Outcome and scope

Implement one continuous iOS Session for text, screenshots, contact proposals,
and receipts. Existing Sessions use native stack navigation. The empty input
supports deliberate hold-to-talk, while text, IME composition, and toolbar
controls preserve their existing ownership. Answers offer compact accessible
feedback controls; whole-Session share and fork live in the navigation menu.

The surface is iOS capture and Session review for an independent recruiter:
quiet, dense enough for continuity, with exact source provenance one action away.
Session is a projection; evidence, proposals, reviewed state, and receipts retain
their own authority. No proposed contact or generated answer executes a write.

- Ask now pushes on the archive's native NavigationStack. A fresh composer keeps
  an explicit close control; its first submitted turn reveals native back and a
  whole-Session menu without replacing the view or conversation state.
- Empty-input hold recognition uses the measured editor and voice-control frames.
  Typed text, whitespace, marked text, attachments, and busy state block voice.
- Responses use AgentMarkdownView and 44-point regenerate/copy/feedback targets.
  Share/fork live only in the navigation menu. Forked screenshot content remains
  stale read-only history; source task references grant no resume authority.
- Contact proposals restore by Session, preserve the original source message,
  block saves without real context, rerun identity lookup after material edits,
  and retain unknown-write recovery. Successful receipts return to the same
  chronological conversation. Declining preserves the original user message.
- Screenshot service results upsert their original Session turn and retain task
  references for canonical readback. Decisions remain inline; completed detail
  stays on demand. Restored running tasks poll readback without rerunning tools.
- Active composer drafts and scoped retries now use per-Session state APIs.
  Canonical synchronization gates Chat admission; response, feedback, receipt,
  read-state, and delete changes schedule synchronization.

## Admission interruption correction

A screenshot upload can be accepted before its task ID reaches the client. The
Session now protects a screenshot-specific pending key, immutable objective,
ordered metadata fingerprint, and original whole-second capture timestamp before
admission. No raw image data enters recovery storage. A restored pending upload
opens a reattachment/reconciliation gate; it cannot replay as an ordinary text
Ask or be replaced by another image, scope, or objective. Reattaching the exact
images retries the existing idempotent create endpoint, including its original
timestamp because the backend hashes that field. Only the matching admission
receipt clears the pending state; older task readback cannot clear it.

Added `AskScreenshotAdmissionPolicyTests` for input-kind routing and exact
ordered metadata fingerprints, plus a relaunch UI recovery case. The Chinese,
dark, AX5, reduced-motion UI case captures Markdown/table/code/menu reachability;
it does not claim physical-device VoiceOver verification. The parent reported
499 existing/new state unit tests passing before these final three policy tests
were added; final integrated unit/UI proof remains parent-owned.

## Review corrections

Open proposal UI now checks the model's current intent authority before edits,
identity lookup, or save. An ended proposal keeps its source visible and offers
only dismissal; a fresh message is required to create a new proposal. The model
owns retirement and unknown-outcome recovery. A deterministic ended-open-card
UI regression complements the state worker's expiry/relaunch coverage.

Screenshot create, restore, poll, resume, and cancel capture an explicit Session
owner and task identity. Every delayed response checks that owner again before
changing the surface or recording the result. A late original-Session response
cannot install live screenshot controls into its fork. The pure response-owner
policy has a bounded regression for the original/fork and mismatched-task cases.

Canonical admission synchronization now requires only the Session being sent.
Scoped responses use strict ownership recording so deletion or expiry during a
request cannot silently create a new Session. Fork continuation discloses when
only recent context fit within the byte bound, keeping the complete original
available. The parent reported the three native voice interaction cases passing;
remaining integrated UI proof and source typechecking remain parent-owned.

## Screenshot capacity and fork ownership

A full screenshot history now blocks admission before the composer clears or a
request is sent. The notice points to the Session menu's fork action, preserves
selected images and the objective, and avoids a Retry action that cannot help.
The fork retains the composer draft and reserves screenshot headroom through the
model's bounded copy. Accepted creation only clears images after its Session
receipt persists, so a persistence error retains reconciliation inputs.

Fork restoration distinguishes inherited read-only screenshot references from
new tasks created in that fork. Only owned task references are restored; inherited
callbacks cannot rebind the Session or activate controls. The pure callback policy
has a regression proving that a new fork-owned task succeeds while an inherited
task remains read-only.
