# Screenshot Agentic flow hardening

## Outcome

Close the three directly observed gaps in the authenticated Web
screenshot-to-contact loop and add a compact adversarial regression program:
ambiguous same-name identities must not be bindable, Wiki compilation must
never silently no-op, and screenshot-provider failures must explain the
recoverable configuration class without exposing credentials.

## Boundary

In scope:

- authenticated desktop Web screenshot capture and identity-binding UI;
- relationship Agent Wiki compilation from the visible Wiki control;
- provider admission/readiness and timeout error classification;
- deterministic tests plus a targeted rendered browser retest;
- independent safety and recruiter-workflow test-case proposals.

Out of scope:

- automatic database deduplication or destructive person merging;
- autonomous fact confirmation or external Contacts, Calendar, ATS, CRM, or
  messaging writes;
- production secret or network changes;
- unrelated iOS edits already in the worktree;
- a full unbound-evidence persistence model if the current backend contract
  cannot support it safely in this slice.

## Current evidence

- The prior agentic run completed extraction, evidence review, no-action, Wiki
  compilation, and refresh readback.
- Four indistinguishable Leila Hartmann rows were selectable; the local
  database contained 119 active same-label subjects.
- `Compile Wiki` called the general `ask()` path, which returns immediately
  when the Ask objective is empty.
- Provider admission currently returns one generic unavailable message, and a
  provider timeout returns one generic analysis failure even when the likely
  recovery is provider-specific network/proxy configuration.

## Design read

Primary surface: desktop evidence review and living relationship workspace.
Audience: an independent recruiter under time pressure. Visual character:
quiet, compact, provenance-first, with warning weight reserved for the one
identity decision that cannot safely proceed. The Agent coordinates analysis
and compilation; governed people, evidence, facts, and effects retain
authority.

## Milestones

1. **Inspect and freeze — completed.** Confirmed exact code paths, existing
   tests, and reviewer-scenario pressure points while preserving unrelated
   iOS work already in the tree.
2. **Identity gate — completed.** Expose stable distinguishing clues, detect truly
   indistinguishable same-name candidates, disable binding/new-person creation
   for that conflict, and provide an explicit recovery explanation.
3. **Agent and provider recovery — completed.** Give Wiki compilation a scoped built-in
   objective, and classify disabled AI, sensitive-processing admission,
   credentials, and provider timeout states without leaking secrets.
4. **Verification — completed.** Focused Web tests, route tests, Web typecheck,
   lint, and documentation checks passed on 2026-08-30. The authenticated
   browser surface proved empty-composer Wiki compilation and the same-name
   fail-closed identity state.
5. **Adjudication and handoff — completed.** Independent safety, workflow,
   provider, identity, Wiki, and implementation reviews were consolidated into
   one regression matrix and a rendered hardening retest record.

## Completion evidence

- ambiguous same-name fixture cannot reach review or commit;
- distinguishable same-name fixture remains selectable using visible clues;
- `Compile Wiki` works with an empty Ask composer and announces loading/result;
- provider-disabled and provider-timeout states return distinct, actionable,
  credential-safe codes/messages while retaining local retry state;
- focused tests and Web typecheck pass;
- rendered browser screenshots demonstrate the changed states;
- a versioned multi-agent case matrix names fixtures, expected gates, and proof.

## Reconsider when

If safely preserving an unresolved screenshot requires a new canonical backend
object, stop at a blocking UI gate for this slice and plan that persistence
contract separately. Do not simulate an unresolved save in client state or
allow the Agent to choose a person on the recruiter's behalf.
