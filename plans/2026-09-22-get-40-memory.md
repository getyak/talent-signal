# GET-40 phase 1 · three-scope Memory backend, contracts, Agent integration

## Outcome

Deliver the real backend half of GET-40: one bounded Memory review domain in the
existing PostgreSQL/Fastify backend with three logical scopes (`self`, `person`,
`relationship`), additive contracts, typed Agent recall/stage integration in
both the ordinary conversation and the scoped relationship Ask, and
deterministic unit + PostgreSQL integration tests. A human commit is the only
way accepted memory or a contact is created; models can only recall and stage.

This phase does **not** deliver the shared Web UI, native iOS UI, production
runtime acceptance, real-model evaluation, or the visual three-state component.
Those remain for the parent/second phase and are listed under "Remaining".

## Model

- `memory_items` — accepted memory: one independently understandable statement,
  scope, explicit subject/relationship dependence, statement kind (`fact`,
  `source_statement`, `user_opinion`), speaker/reporter, valid/observed time,
  version, supersede/conflict links, sensitivity, status.
- `memory_item_evidence` — independently retained minimal excerpt + locator +
  original lineage (capture/resource/fragment or Session/message/artifact).
  Natural Session/image TTL does not revoke it; explicit Session, capture, or
  media deletion, authorization revocation, identity rebind, or item deletion
  does.
- `memory_proposals` / `memory_proposal_items` — frozen staged candidates with
  `subject_kind` (`owner_self`/`resolved_subject`/`proposal_target`),
  `relationship_kind`, per-item admission + `judgment_kind`, default selection,
  previous target/version, provenance and exact source excerpt.
  `added_revision` freezes late additions out of an open review.
- `memory_review_scopes` — server-issued binding of reader, purpose, proposal
  revision, allowed item set, source Session/message, and credential hash.
- `memory_review_drafts` — resumable, non-canonical selection/edits/decisions
  keyed by proposal, merged per surface so a restricted save never drops
  private Chat choices.
- `memory_commits` / `memory_commit_items` / `memory_receipts` — idempotent
  receipt, decision ledger, undo token and limits.
- `memory_proposal_rebases`, `memory_projection_jobs` — guarded identity rebase
  log and Wiki/index rebuild outbox. Accepted memory immediately supersedes
  affected knowledge snapshots and bumps the harness source generation.

## Decisions

1. Recall is scope-first and authentication-first: `self` is private to the
   acting user; `person`/`relationship` need an active subject/context and are
   never serialized on a restricted surface.
2. `contact_status` is derived from the account directory. A new-contact name is
   a source-grounded draft (`proposal_target`), not an asserted identity; a
   same-name directory conflict is `ambiguous`. A stable identity clue derives
   a deterministic `subjects.external_ref`, so a concurrent duplicate create
   fails closed.
3. Commit is all-or-none per review scope. A skipped contact saves only `self`
   items and leaves person/relationship items pending so restoring the same
   identity recovers the prior selection. A partial commit bumps the proposal
   revision and rebases the remainder.
4. Conflicting/sensitive/ambiguously-attributed items are not default-selected
   and need an explicit typed decision. Any edited display text is conservatively
   user-edited with the original quote retained.
5. Undo is version-bound compensation; it refuses to overwrite a later version
   and never revives a version whose source is no longer authorized. Contact
   reclaim checks captures, memory, assignments, handles, profiles, manifests.
6. No regex-only business extraction. Candidates are staged by the bounded model
   through the typed Agent tool; the server validates grounding, dependence,
   admission, duplicates, and target revisions.

## API handoff (parent builds UI/runtime acceptance on these)

All authenticated `bearerSession`, account-scoped, additive to existing
contracts. Exact routes live in
`apps/backend/src/modules/memoryReviewRoutes.ts`.

- `GET /v1/memory/proposals?purpose=&person_id=&relationship_context_id=` —
  purpose-scoped list; people/relationship require the exact contact and never
  return private self counts or ids.
- `POST /v1/memory/proposals` — untrusted staging request. The server loads the
  authenticated Session message/ordered images itself; the body cannot carry
  source text or artifact authority.
- `POST /v1/memory/proposals/:proposalId/reviews` — open/reuse a purpose-bound
  review scope and return a one-time `review_credential`.
- `POST /v1/memory/proposals/:proposalId/rebases` — guarded identity rebase.
- `GET /v1/memory/reviews/:reviewScopeId?credential=` — read the frozen view.
- `PUT /v1/memory/reviews/:reviewScopeId/draft?credential=` — merge local draft.
- `POST /v1/memory/reviews/:reviewScopeId/commits?credential=` — atomic commit.
- `GET /v1/memory/operations/:operationKey` — receipt readback; a revoked source
  returns `source_revoked` instead of the old payload.
- `POST /v1/memory/commits/:commitId/undo`
- `GET /v1/memory/items?surface=&person_id=&relationship_context_id=&limit=`
- `POST /v1/memory/items/:itemId/mutations` — versioned correct/delete.

Response types are the additive `packages/contracts/src/memorySchemas.ts`
exports. Unscoped Chat agent events add `memory_proposal`; scoped relationship
Ask adds `ChatTaskResponse.memory_proposal`.

## Source-authority correction (round 2)

Pending review authority is now separate from accepted retained evidence:

- Pending reads, drafts, commits, and reproposals reconstruct the original
  admitted source and reject when the exact Session/message is deleted,
  expired, purged, or has changed message text or ordered image
  attachment/digest. `visibleReviewItems` drops items whose source is no longer
  available instead of returning expired pending text.
- Commit revalidates the proposal source snapshot and every selected item under
  `FOR SHARE` row locks on the original Session, conversation images, captures,
  resources, retention receipts, and fragments. This runs even for a
  contact-only commit (`selected.length === 0`).
- Accepted minimum evidence keeps independent retention: a commit before
  natural TTL survives recall; an explicit Session/capture/artifact deletion or
  authorization revocation immediately removes dependent memory.
- `memory_source_revocations` is epoch-aware via `captures.version`: an
  explicit delete writes an all-epoch tombstone, while an explicit revoke or
  identity rebind tombstones only the revoked capture version so a later
  restore/rebind can stage fresh evidence while the old epoch stays gone. The
  `correctCaptureIdentity` hook reads and locks the old capture version before
  recording the old-epoch tombstone. Natural source-authorization expiry does
  not invalidate accepted Memory.
- `rebaseMemoryProposal` preserves the draft and reactivates items for a
  restored target; `regenerateMemoryProposal` runs the bounded proposer outside
  the SQL transaction and version-guards the final write, keeping the
  relationship label in `relationship_display_label` rather than a UUID column.
- Review scopes now hold multiple independent credentials
  (`memory_review_credentials`), so a second same-revision tab no longer
  invalidates the first; a stale commit still reconciles on revision.
- A source/revision-scoped dismiss action marks reviewed items declined without
  creating memory, a contact, or a commit receipt.

## Semantic correction (round 3)

- Temporal non-destructiveness: `classifyTemporalRelation` returns `separate`
  when a new future plan meets a non-future fact; stage derives effective
  `operation = add` and clears the previous target so the plan never supersedes
  the fact. A future plan replaced by new evidence of completion still updates,
  and same-plan reschedules still update. Commit persists the effective
  operation, so stage/review/commit agree.
- Pending-contact self escape: candidates declare `dependence_kind`
  (`independent_self` / `contact` / `relationship`), so a contact-dependent
  sentence is bound to the proposal target even before a UUID exists. A host
  consistency check flags an undeclared self sentence that names the current
  contact/identity clue, and commit applies the same invariant to edited text.
- Explicit revoke/restore: `decideCaptureSourceAuthorization` now calls
  `invalidateMemoriesForCaptureIds(..., 'source_revoked', oldVersions)` in the
  same transaction, permanently revoking accepted Memory evidence and
  tombstoning the revoked capture version; restore leaves the old epoch gone,
  while a new epoch can stage and accept fresh evidence.
- Pending capture deadline: the pending verifier now requires the current
  source-access authority (`authorization_state = authorized`,
  `source_access_state = available`, future `authorization_expires_at` and
  `retention_until`), so a passed deadline fails review closed before the sweep;
  accepted minimum evidence still survives natural TTL.
- Pure-image host: the raw user source text is separated from the provider
  instruction, so an images-only message persists an empty user objective, the
  proposal binds the empty-message snapshot, and the real host stages and
  commits 17 items.
- Relationship host: the Chat relationship text artifact is bound to the
  Session message id (not a fabricated media-looking string), and the verifier
  decides media vs session authority by real `chat_media_assets` rows rather
  than string guesses.
- Regeneration: the regenerator receives the ordered admitted images, runs the
  provider outside SQL, regenerates for both existing and new identity changes,
  preserves choices on same-identity restore, and records a real failure without
  writing when the model is unavailable.
- Idempotent scope binding: the commit idempotency request includes the review
  scope id and replay verifies the committing scope, so an operation key cannot
  be replayed through another legitimate scope to return private ids.
- Helpful answer: an authorized search/read/recall/stage may now end in a
  helpful answer (with the resolved-contact provenance event and an optional
  memory reference) instead of forcing `use_contact`.
- Conflict undo: undoing a conflict batch no longer clears the conflict group
  when a later active conflict still shares it.
