# PR 18 core-loop focus plan

## Outcome

Turn the current cross-surface foundation into one judgeable iOS loop that
demonstrates the original product value in under three minutes:

```text
intentional synthetic capture + optional recruiter context
→ exact evidence
→ atomic fact review
→ reviewable contact and meeting action cards
→ recruiter decisions
→ one evidence-backed momentum insight
→ truthful local outcome
```

The loop should make the post-confirmation insight the product payoff. It must
remain explicit that this slice does not OCR arbitrary images and does not write
to Contacts, Calendar, ATS, CRM, or messaging systems.

## Why this matters

PR 18 has strong evidence, authority, recovery, and cross-surface foundations,
but its most visible iOS path still leads with a fixture selector and ends with
a generic local question handoff. That demonstrates governance better than the
original screenshot-to-action-to-insight promise.

The smallest useful correction is a focused iOS hero loop that reuses the
existing fact-review machinery, adds typed action-card decisions, and reveals
an insight only after those decisions.

## In scope

- one synthetic, clearly labeled hero conversation;
- one optional recruiter-context field;
- exact evidence and existing atomic fact review;
- typed `update_contact` and `create_meeting` action cards for the hero case;
- domain support for `create_contact` with deterministic tests;
- approve or dismiss on every action card;
- one `advance`, `resolve_blocker`, `at_risk`, or `wait` insight derived from
  accepted facts, approved cards, prior contact context, and recruiter context;
- a truthful local handoff outcome;
- focused unit tests and direct iOS surface evidence.

## Out of scope

- production OCR or arbitrary-image binding;
- model-provider or prompt changes;
- real Contacts, Calendar, ATS, CRM, notification, or message writes;
- browser-extension, Codex-plugin, and backend authority redesign;
- changing the frozen eight-case cross-surface fixture contract;
- App Store release approval or field-value claims.

## Frozen baseline

- PR: `#18`
- branch: `codex/round-4-final-integration`
- baseline commit: `a7b53d1`
- primary surface: iOS
- target user: time-constrained independent recruiter
- environment: local iPhone Simulator with synthetic data only
- required scenario: Alex Chen has another offer, a Wednesday decision
  deadline, a strong remote preference, and explicit Tuesday meeting consent;
  recruiter context confirms APAC remote eligibility and prior relationship
  history.

Uncommitted CI, backend, iOS safe-area, and test-recovery work already present
in the shared PR worktree is unrelated user work and must be preserved.

## Chosen approach

1. Add a small domain-only hero catalog rather than mutating the frozen fixture
   suite.
2. Reuse `ReviewSession` and fact decisions.
3. Build action cards deterministically from reviewed facts and explicit
   meeting consent.
4. Require an explicit decision on every card.
5. Reveal one insight only after card review.
6. Keep the final effect local and honest.

## Rejected alternatives

- **Real OCR first:** too much risk for the shortest product-value proof; it
  would consume the loop budget before insight quality is testable.
- **Real Contacts/Calendar writes first:** raises permission, duplicate,
  reconciliation, and recovery scope before the recommendation is proven.
- **Web-first loop:** faster to code, but the requested final form is iOS and
  the current iOS foundation is already substantial.
- **More cross-surface governance:** already well represented in PR 18 and does
  not address the original brief's missing payoff.
- **Insight before review:** violates the intended sequencing and encourages
  unsupported interpretation.

## Milestones

### 1. Domain loop

Pass when:

- the hero case opens without changing the eight-case fixture suite;
- reviewed facts produce exact typed action cards;
- availability without consent never produces a meeting card;
- an unmatched person with explicit contact evidence can produce a
  `create_contact` card in a deterministic test;
- insight is unavailable until every action card has a decision.

### 2. iOS hero path

Pass when:

- the first screen gives the hero loop visual priority;
- optional recruiter context is visible and purpose-limited;
- existing evaluation fixtures remain available under secondary disclosure;
- action cards show type, target, patch/effect, reason, and supporting evidence;
- approve and dismiss are distinct without color-only meaning;
- the insight appears only after card review and names why now, the current
  dependency, one next step, and timeframe.

### 3. Verification

Pass when:

- focused unit tests pass;
- the Release simulator build succeeds;
- the hero path is directly exercised on Simulator;
- existing relevant unit tests still pass;
- no unrelated worktree changes are overwritten;
- the final handoff clearly separates demonstrated behavior from unimplemented
  OCR and external writes.

## Completion evidence

- source and test diff limited to the hero loop and its plan;
- command output for focused iOS tests and Release build;
- a Simulator screenshot or recording showing the post-decision insight;
- final `git status` demonstrating unrelated changes remain preserved.
